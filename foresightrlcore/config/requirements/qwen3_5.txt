# Container requirements for qwen3_5 recipe (vLLM-enabled).
# Used by: SageMaker launcher (via recipes.py) and intuit/docker/Dockerfile.qwen3_5.
# To add a new package: edit this file. No code changes needed.
# The training-stack trio is pinned exactly, not range-bounded. Recipe specs
# are resolved by pip *inside the container at job start*, so an open range
# re-resolves against live PyPI on every run and a green recipe turns red with
# no code change. Three upstream releases have done exactly that, and they set
# the upper bound on each pin:
#   * trl 1.11 replaced the in-process LLM(...) call in scripts/vllm_serve.py
#     with an os.execve of `vllm serve`, so patch_trl_vllm.py can no longer
#     apply and vLLM never starts. Requires trl < 1.11.
#   * vllm 0.28 deleted NCCLTrainerSendWeightsArgs from
#     distributed.weight_transfer.nccl_engine, which every trl in the 1.6-1.10
#     window imports at trainer-import time. Requires vllm < 0.28.
#   * transformers 5.16 dropped `logging_dir` from TrainingArguments, which
#     GRPOConfig inherits and methods/base.py passes. Requires transformers
#     < 5.16.
#
# vllm moved 0.23.0 -> 0.26.0 on 2026-09-09 to clear 14 CVEs (CVE-2026-12491,
# -53923, -54233..54236, -55514, -55574, -55646, -71486, -73555..73557,
# -73559), all fixed in 0.26.0. 0.26.0 is the highest safe step: it keeps
# torch==2.11.0 / torchvision==0.26.0 / torchaudio==2.11.0 exactly as 0.23.0
# had them, so nothing in the CUDA stack is rebuilt, whereas 0.27+ moves to
# torch 2.13.0 and 0.28 drops the symbol above.
#
